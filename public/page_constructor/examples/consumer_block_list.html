Пример потребителя block_list в шаблоне

Это справочный файл, а не продакшн-шаблон. Конструктор отдаёт JSON формата v2 ({schema, version, blocks}, пример — examples/example_block_list.json); бэкенд парсит его и передаёт в шаблон список block_list.

Статус партиалов. Реестр — templates/_shared/contract/blocks.json. Часть блоков уже используется в prod (advantages, reviews, clients, services, faq, header, footer, subscribe), остальные помечены planned/kind: preview. Существующие партиалы читают данные из верхнеуровневых переменных (advantages_list и т.п.), а не из block.* — при переезде на block_list их нужно нормализовать (block.items → ожидаемая переменная).

Нормализация данных под существующие партиалы

{# goods: товары подгружает движок, block.params → data-атрибуты goods-block #}

              data-cols="{[[ block.params.cols ]]}"></goods-block>

Классы конверта: block.fill → block--fill-N, block.anim → block--anim-*/block--no-anim, block.bleed → block--bleed. Структурные классы блоков — в classes.json → page_constructor.
